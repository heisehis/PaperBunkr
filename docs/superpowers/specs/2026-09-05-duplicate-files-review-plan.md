## Step 2: `SmartListQueryBuilder.BuildDuplicateGroups`
**Files:** `src/Paperbunkr.Data/SmartLists/SmartListQueryBuilder.cs` (edit — add the method near the existing `DuplicateIssueIds`, leaving that method untouched).
**What:** `public static List<List<Issue>> BuildDuplicateGroups(IReadOnlyCollection<Issue> issues)` — union-find over the same two keys `DuplicateIssueIds` already uses (metadata tuple `(SeriesId, Format, Count, EffectiveNumber(), EffectiveVolume(), LanguageISO, EffectiveYear(), Month, Day)`, or identical non-empty `FilePath`). Two issues sharing either key land in the same cluster. Return only clusters with `Count >= 2`. Sort each cluster's members: `FileIsMissing` ascending, then `FileSize` descending (nulls last), then `AddedTime` ascending, then `Id` ascending — per the design's tie-break rules, so index `[0]` is always the correct default "keep."
**Depends on:** none (independent of Step 1's column).
**Verify:** new tests in `src/Paperbunkr.Data.Tests/SmartListQueryBuilderTests.cs`:
- `BuildDuplicateGroups_UnionsIssuesLinkedByEitherKey_IntoOneCluster` — issue A matches B by metadata key, B matches C by file path only (different metadata) → all three in one cluster.
- `BuildDuplicateGroups_ExcludesSingletons` — an issue matching nothing stays out entirely.
- `BuildDuplicateGroups_SortsFileIsMissingLast_ThenBySizeDescending_ThenDeterministicTiebreak` — a missing-file issue never sorts first even if it's otherwise "larger" (null size); equal sizes fall back to `AddedTime` then `Id`.

## Step 3: `LibraryFolderScanner` reports which issues it added
**Files:** `src/Paperbunkr.App/Services/LibraryFolderScanner.cs` (edit).
**What:** `LibraryFolderScanResult` gains a third field: `public record LibraryFolderScanResult(int IssuesAdded, int SeriesTouched, IReadOnlyList<int> AddedIssueIds);`. In `ImportFiles`, collect each newly-created `Issue` into a `List<Issue> addedIssues` (alongside the existing `issuesAdded++`/`seriesTouched.Add(...)`), and after `context.SaveChanges()` (so each has a real `Id`), pass `addedIssues.Select(i => i.Id).ToList()` into the final `new LibraryFolderScanResult(...)`. Single construction site (`return new LibraryFolderScanResult(issuesAdded, seriesTouched.Count);` at the end of `ImportFiles`) — no other call site constructs this record.
**Depends on:** none.
**Verify:** existing `LibraryFolderScannerTests` still pass (they read `IssuesAdded`/`SeriesTouched`, unaffected by the new field); add one new case asserting `result.AddedIssueIds` contains exactly the ids of the newly-created issues.

## Step 4: New row ViewModels + `NeedsReviewViewModel` section
**Files:** new `src/Paperbunkr.App/ViewModels/DuplicateCandidateViewModel.cs`, new `src/Paperbunkr.App/ViewModels/DuplicateGroupRowViewModel.cs`, edit `src/Paperbunkr.App/ViewModels/NeedsReviewViewModel.cs`.
**What:**
- `DuplicateCandidateViewModel`: holds `IssueId`, `FileName` (from `FilePath` via `Path.GetFileName`), `SizeLabel` (small local byte-formatter, B/KB/MB/GB/TB — same units/style as `IssueListFieldCatalog.FormatFileSize`, not shared/reused since that method is `private` to an unrelated file and the formatter is ~10 lines), `DateLabel` (`AddedTime?.ToString("MMM d")`, matching `ActivityConverters`' existing date format), `GroupKey` (string, set by the parent group — feeds `RadioButton.GroupName` in XAML so mutual exclusion works per-group even though every group's `ItemsControl` shares one visual tree), and `IsKeep` (bool, `[ObservableProperty]`, two-way bound to the RadioButton's `IsChecked`).
- `DuplicateGroupRowViewModel`: `GroupLabel` (e.g. `"Kilo Station #012 · 2 copies"`, series name + effective number + candidate count — same label shape `MissingFileRowViewModel` already uses), `ObservableCollection<DuplicateCandidateViewModel> Candidates`, `ResolveCommand` (calls back `onResolve(this)`), `DismissCommand` (calls back `onDismiss(this)`). Exposes the currently-`IsKeep`-selected candidate for the parent to read when resolving.
- `NeedsReviewViewModel`: add `DuplicateGroupItems` (`ObservableCollection<DuplicateGroupRowViewModel>`), `HasDuplicateFileItems`, fold into `HasPendingItems`/`NotifyCountsChanged`. `RefreshDuplicateFileItems(PaperbunkrDbContext context)` — load `context.Issues.Where(i => !i.IsPlaceholder).ToList()`, run `SmartListQueryBuilder.BuildDuplicateGroups`, keep only clusters with at least one `!DuplicateAcknowledged` member, build one `DuplicateGroupRowViewModel` per cluster. `ResolveDuplicateGroup(group)` — for every non-kept candidate, `LibraryDeletionHelper.RemoveIssue`; `SaveChanges(); Refresh();`. `DismissDuplicateGroup(group)` — set `DuplicateAcknowledged = true` on every issue in the cluster; `SaveChanges(); Refresh();`. `[RelayCommand] KeepLargestInAllGroups()` — call `ResolveDuplicateGroup` for every currently-visible group (each group's pre-sorted `[0]` candidate is already the default `IsKeep`, so this just runs Resolve using whatever's currently selected per group — same "use current state" semantics `MergeAllAboveNinety` already has for conflicts).
**Depends on:** Step 1 (`DuplicateAcknowledged`), Step 2 (`BuildDuplicateGroups`).
**Verify:** new cases in `src/Paperbunkr.App.Tests/NeedsReviewViewModelTests.cs` (or a new file if that one doesn't exist yet — check first):
- `Refresh_GroupsDuplicateIssues_ExcludingFullyAcknowledgedClusters`
- `Refresh_ReshowsCluster_WhenNewIssueJoinsAPreviouslyDismissedGroup`
- `ResolveDuplicateGroup_DeletesNonKeptCandidates_KeepsSelected` (assert the kept issue's row survives, others are gone from the DB, and — matching `LibraryDeletionHelper`'s existing contract — no exception when a deleted duplicate is also in a reading list/event).
- `DismissDuplicateGroup_AcknowledgesEveryCurrentMember`
- `KeepLargestInAllGroups_ResolvesEveryVisibleGroup`

## Step 6: Proactive alert wiring
**Files:** new `src/Paperbunkr.App/Services/DuplicateAlertHelper.cs`, edit `src/Paperbunkr.App/Services/LiveFolderWatchService.cs`, edit `src/Paperbunkr.App/ViewModels/PreferencesScreenViewModel.cs`, edit `src/Paperbunkr.App/ViewModels/MainViewModel.cs`.
**What:**
- `DuplicateAlertHelper` (static, mirrors `LibraryDeletionHelper`'s shape): `public static void RaiseIfAny(IActivityService activity, IReadOnlyList<int> addedIssueIds)` — no-ops if `addedIssueIds.Count == 0`; otherwise opens a context, loads `context.Issues.ToList()`, runs `SmartListQueryBuilder.BuildDuplicateGroups`, counts clusters containing at least one id from `addedIssueIds`, and if `> 0` calls `activity.RaiseAlert` with `Severity = Warning`, `Title = "Possible duplicates found"`, `Detail` pluralized on the cluster count, `ActionLabel = "Review"`, `ActionLink = new ActivityLink(ActivityLinkKind.MigrationReview)`, `DedupeKey = "duplicate-files"` — exactly the shape in the design doc. One shared helper avoids duplicating this logic across the two call sites below.
- `LiveFolderWatchService`: add a fourth optional constructor parameter `Action<IReadOnlyList<int>>? onFilesImported = null` (both the public and internal test-seam constructors, same pattern as `onFilesMissing` added this session), defaulting to a no-op. In `ImportCreatedFilesAsync`, right after the existing `_showToast("New comics found", ...)` call, invoke `_onFilesImported(result.AddedIssueIds)` when `result.IssuesAdded > 0`.
- `PreferencesScreenViewModel.ScanNow`: right after the existing `if (result.IssuesAdded > 0)` cover-generation block, add `DuplicateAlertHelper.RaiseIfAny(_activity, result.AddedIssueIds);`.
- `MainViewModel`: extend the `LiveFolderWatchService` construction (already edited this session for `onFilesMissing`) with `onFilesImported: ids => DuplicateAlertHelper.RaiseIfAny(Activity, ids)`.
**Depends on:** Step 2 (`BuildDuplicateGroups`), Step 3 (`AddedIssueIds`).
**Verify:** new case in `src/Paperbunkr.App.Tests/LiveFolderWatchServiceTests.cs`: `Created_FileDuplicatingExisting_InvokesOnFilesImported_WithAddedIds` (seed an existing issue, drop a watched-folder file that duplicates it by metadata, assert the callback fires with the new issue's id). `ActivityServiceTests`/`ActivityCenterViewModelTests` need no changes (dedupe-by-key behavior already covered generically). Manual: same on-screen check as the missing-files alert — trigger a duplicate import, confirm the alert appears once and links to the new Needs Review section.
