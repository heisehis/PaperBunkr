# Library Redesign, Slice 1 (Command Bar and Lenses) — Implementation Plan
*Implements: docs/superpowers/specs/2026-10-04-library-redesign-design.md (Slice 1)*

Survey findings that shape this plan (2026-10-04):

- Read state already has one definition: `IssueMetadataExtensions.IsUnread` (never moved past page 0),
  `HasBeenRead` (>= 95%), `IsInProgress`. The lens uses those; `SeriesCardSample.UnreadCount` is left alone.
- Content type is a **sidebar selection** today (`_activeContentType`, mutually exclusive with a collection, set by
  `SelectContentTypeCommand`). In this slice the Content type chip drives that same state; making it combine with a
  collection and removing the sidebar group belongs to slice 4.
- There is no publisher filter. It is added as a session-only filter, like `SourceFilter`.
- Recent `AppSettings` migrations add a column with a deliberate no-op `Down`.
- `WorkspaceService.EnsureBuiltInsSeeded` only inserts missing built-ins, so redefining "Currently reading" needs an
  explicit update of the existing row.
- `TabStrip.Step` finds buttons classed `tab` + `active`; `LibraryScreen` does not handle `TabNext`/`TabPrevious` yet.
- The View & Sort popup keeps its Display mode / Card content lists (UI-automation ids depend on them); row 1 gains
  quick switches for the same state.

## Step 1: Lens enum, setting and migration
**Files:** `src/Paperbunkr.Data/Entities/LibraryLens.cs` (new), `Entities/AppSettings.cs`, `PaperbunkrDbContext.cs`,
`Migrations/*_AddLibraryLens.cs` (+ Designer, snapshot, generated by `dotnet ef migrations add`).
**What:** `enum LibraryLens { All, Reading, Unread, Read }`; `AppSettings.LibraryLens` stored as a string with default
and sentinel `All` (same shape as `LibraryGridCoverFit`). Migration `Down` is a no-op, per the project convention.
**Verify:** `Paperbunkr.Data.Tests` builds and its migration tests pass.

## Step 2: Pipeline
**Files:** `src/Paperbunkr.App/Services/LibrarySearch/LibraryViewPipeline.cs`.
**What:** `LibraryViewInputs` gains `Lens` and `PublisherFilter`. One pass classifies each series (Unread = no issue
opened, Read = every issue read, else Reading) and each issue, tallies `LensCounts` for both granularities over
everything that passed scope, filters and search, then applies the lens. `LibraryViewResult` carries both counts.
**Verify:** new cases in `LibraryViewPipelineTests`.

## Step 3: Workspace state and seeding
**Files:** `Models/WorkspaceState.cs`, `Services/WorkspaceService.cs`.
**What:** `LibraryWorkspaceState.Lens = All` appended. "Currently reading" becomes `Lens: Reading`, sort Opened
descending, no unread filter; the seeder rewrites an existing built-in Library row whose stored state differs.
**Depends on:** Step 1. **Verify:** `WorkspaceStateTests`, `LibraryWorkspaceTests`.

## Step 4: View model
**Files:** `ViewModels/LibraryScreenViewModel.cs`.
**What:** `ActiveLens` (persisted, captured/applied by Workspaces), `SetLensCommand`, per-lens counts and labels for the
active granularity, `ResultSummary`, `PublisherFilter` + options, dropdown ids for the content-type, publisher and
source chips, `ClearAllFilters` covers the publisher, empty-state message names the lens.
**Depends on:** Steps 1–3. **Verify:** `LibraryScreenViewModelTests`, `LibraryWorkspaceTests`.

## Step 5: Toolbar
**Files:** `Views/LibraryToolbar.axaml` (+ `.axaml.cs` if needed).
**What:** Row 1 gains Series | Issues and Covers / List / Details switches; the Filter button and its popup go.
Row 2 is always visible: lens tabs (`tab` + `active`, with counts, dimmed at zero), filter chips in a horizontal
scroller (Content type, Publisher, Has unread, Missing, Tracked, Library source, search scope, Clear), and the
result summary with the existing Sorted / Grouped buttons on the right.
**Depends on:** Step 4. **Verify:** headless view tests; build with the XAML weave confirmed.

## Step 6: Keyboard
**Files:** `Views/LibraryScreen.axaml.cs`.
**What:** claim `TabNext` / `TabPrevious` with `TabStrip.Step` over the toolbar. No new actions.
**Verify:** headless test stepping the lens through the input service.

## Step 7: Tests and docs
**Files:** `Paperbunkr.App.Tests/*` (new lens tests, fixes to tests that relied on the old toolbar), `wiki/The-Library.md`,
`docs/paperbunkr-todo.md`, `docs/ce-feature-inventory.md`.
**Verify:** targeted Library test classes, then `--filter "Speed!=Slow"`. On-screen check is the user's; FlaUI runs
need permission and are not run here.
