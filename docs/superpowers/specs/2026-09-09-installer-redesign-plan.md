# Installer redesign — Implementation Plan
*Implements: docs/superpowers/specs/2026-09-09-installer-redesign-design.md*

Already done before this plan (per the design doc): `Paperbunkr.App.csproj` `<Version>` →
`0.3.0.0`; `Installer.iss` + `BuildInstaller.ps1` version fallbacks → `0.3.0-beta`; Welcome copy
Alpha→Beta; `WizardImage.png` / `WizardSmallImage.png` produced.

**Correction to the design doc (confirmed with user 2026-09-09):** the file-association task list
is **7 formats, not 6** — `.cbt` ("eComic (TAR)") is added back for ComicRack CE parity (CE's own
installer associates `.cbt`; the engine registers a reader for it). The design's decision-5
rationale only argued against generic `.zip`/`.rar`/`.7z`; dropping `.cbt` was an oversight. The
design doc should get a one-line note to this effect.

Comic-association extension allow-list (single source of truth for steps 3 and 5):
`.pdf .cbz .cbr .cb7 .cbt .cbw .djvu`

## Step 3: File-association tasks — split by format (`Installer.iss`)
**Files:** `installer/Installer.iss` (edit)
**Depends on:** Step 5 (the CLI must accept a per-format filter arg)
**What:**
- Replace the single `associate` `[Tasks]` entry with 7 entries (all `Flags: unchecked`,
  `GroupDescription: "Additional options:"`), one per format:
  `associatepdf` (.pdf), `associatecbz` (.cbz), `associatecbr` (.cbr — covers both the RAR and
  RAR5 provider registrations), `associatecb7` (.cb7), `associatecbt` (.cbt), `associatecbw`
  (.cbw), `associatedjvu` (.djvu). Descriptions name the extension and the format
  ("Associate .cbz comic archives with Paperbunkr", etc.).
- `[Run]`: replace the one `--register-file-associations` line with 7, each
  `Parameters: "--register-file-associations <ext>"`, `Tasks: associate<fmt>`,
  `Flags: runhidden waituntilterminated`, `StatusMsg: "Registering .<ext> association..."`.
- `[UninstallRun]`: mirror — 7 `--unregister-file-associations <ext>` lines, each
  `Tasks: associate<fmt>`, distinct `RunOnceId`.
- Update the file-header deviation-#2 note and the `[Tasks]`/`[Run]`/`[UninstallRun]` comments to
  describe the per-format split and cite design decision 5 + the `.cbt` correction.
**Verify:** built setup shows 7 separate checkboxes; selecting only `.cbz` then finishing
registers exactly `.cbz` (check `HKCU\Software\Classes\.cbz` and that `.zip`/`.rar`/`.7z` are
untouched); uninstall with that task selected removes it. Manual + the Step 7 automated check
covers the CLI filter itself.

## Step 4: Existing-install gate — `InitializeSetup` (`Installer.iss` `[Code]`)
**Files:** `installer/Installer.iss` (edit)
**Depends on:** none
**What:** add to the existing `[Code]` section (keep `CurUninstallStepChanged` as-is):
- A `const UninstallRegKey` with the literal
  `Software\Microsoft\Windows\CurrentVersion\Uninstall\{E6F64297-BD9E-4341-A156-5C65C2E6C1DB}_is1`
  (hardcode the GUID — it equals the `[Setup]` `AppId`, which is commented "generated once, never
  regenerate"; deriving it via `{#SetupSetting("AppId")}` mangles the `{{` escape). Comment the
  tie.
- Helper funcs: `GetInstalledUninstallString()` and `GetInstalledDisplayVersion()` —
  `RegQueryStringValue(HKLM, ...)` then `HKCU` fallback.
- `function InitializeSetup(): Boolean;` implementing the three-way branch from design decision 7:
  - not found → `Result := True`.
  - found, `DisplayVersion` = `{#MyAppVersion}` → `MsgBox` (or `SuppressibleMsgBox`) offering
    Repair vs Uninstall (custom 3-button or a Yes/No/Cancel mapping). Uninstall → `Exec` the
    uninstall string (`/SILENT`? no — let its own prompts run), then `Result := False`. Repair →
    `Result := True` (falls through; `UsePreviousAppDir` pre-fills the path).
  - found, `DisplayVersion` ≠ → single lighthearted "welcome back / ready to move up to
    {#MyAppVersion}?" `MsgBox` in `WelcomeLabel`-matching tone, reading the old version into the
    text. Next/OK → `Result := True`; Cancel → `Result := False`.
  - Guard the whole thing with `if not WizardSilent()` / check `InitializeSetup` is allowed to
    prompt — a silent/auto-update re-run (NetSparkle) must not block. On silent, skip straight to
    `Result := True` (let the normal reinstall-over-existing flow run).
- Exact prompt wording is implementation-detail (design says not frozen); keep it short and in
  the established voice.
**Verify:** Manual matrix — (a) fresh machine: no prompt, straight to Welcome; (b) re-run same
exe over an install of the same version: Repair/Uninstall dialog, both branches behave; (c) build
a fake older-version uninstall registry entry (or install an older build): upgrade prompt shows
the old version string, Next proceeds over the existing dir, Cancel aborts clean; (d)
`setup.exe /SILENT` over an existing install: no prompt. **Manual — Inno `[Code]` has no unit
harness here.**

## Step 5: Scope the CLI association path to comic formats (`Program.cs` + `FileAssociationService`)
**Files:** `src/Paperbunkr.App/Services/FileAssociationService.cs` (edit),
`src/Paperbunkr.App/Program.cs` (edit)
**Depends on:** none
**What:**
- `FileAssociationService`: add
  `public static readonly IReadOnlyList<string> ComicAssociationExtensions =` the 7-ext allow-list,
  and a method
  `public void SetComicAssociationsFor(IEnumerable<string> extensions, bool associate)` that:
  loops `Providers.Readers.GetSourceFormats()`, keeps only formats whose extension set intersects
  **both** `ComicAssociationExtensions` and the passed `extensions` (case-insensitive, tolerate
  missing leading dot), and calls the existing per-format `SetAssociated(format.Name, associate)`.
  This keeps one owner of the registry keys and leaves `GetAvailableFormats()` (Preferences →
  Advanced) completely untouched. XML-doc it citing design decision 5.
- `Program.cs`: change the `--register-file-associations` / `--unregister-file-associations`
  interception to parse trailing args as the extension list; when none are passed, default to the
  full `ComicAssociationExtensions` set (so a bare invocation still does something sensible and
  never re-associates `.zip`/`.rar`/`.7z`). Call `SetComicAssociationsFor(...)` instead of the
  current "loop every `GetAvailableFormats()` entry". Update the comment block.
**Verify:** new xUnit tests (Step 7). Also: `dotnet build src/Paperbunkr.App/Paperbunkr.App.csproj`.

## Test strategy summary

- **Automated:** only Step 7 (the `FileAssociationService` comic-format filter) — the one piece
  with real unit-testable logic. Run via targeted `--filter`, never the full suite (headless
  flake under concurrent load, per project memory).
- **Build gate:** `dotnet build src/Paperbunkr.App/Paperbunkr.App.csproj` after Step 5;
  `pwsh installer/BuildInstaller.ps1` (needs Inno Setup 6.7.3 + a `dotnet publish`) after each
  `Installer.iss` / `BuildInstaller.ps1` change — a clean ISCC compile with zero warnings is the
  bar.
- **Manual / on-screen (unavoidable for Inno wizard + `[Code]`):** Steps 1–4 each list their own
  click-through matrix. The wizard-branding and existing-install-gate behaviour can only be
  confirmed by running the built `setup.exe` on light- and dark-theme Windows sessions and
  against pre-seeded uninstall-registry states.
- Per project rule: do **not** run `installer/BuildInstaller.ps1` end-to-end unless asked — it's
  a heavy publish+package. Directive-level correctness can be checked with a bare
  `ISCC Installer.iss` compile against stub `publish/*.txt` files during development.
